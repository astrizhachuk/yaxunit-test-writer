# yaxunit-test-writer

Навык для ИИ-агентов, устанавливаемый через [skills CLI](https://github.com/vercel-labs/skills),
для написания юнит-тестов конфигураций 1С:Предприятие на фреймворке
[YAxUnit](https://github.com/bia-technologies/yaxunit).

Навык проводит агента через весь цикл написания теста: подготовка тестового
модуля и его регистрация в расширении с тестами, проектирование тестов (типы,
именование), реализация given/when/then, изоляция зависимостей через Мокито,
организация тестовых наборов и тегов. Срабатывает на фразы вида «напиши тест»,
«покрой тестами», «яксюнит».

Поддерживаются обе среды разработки 1С: выгрузка Конфигуратора и проекты
1C:EDT. Код тестов одинаков для обеих; различаются только файлы метаданных,
их раскладка и регистрация.

## Установка

Устанавливается под любого поддерживаемого `skills` агента (Claude Code, Cursor,
Codex, Windsurf, Cline и др.) — флагом `-a` указывается целевой агент, ниже
пример для Claude Code. `astrizhachuk/yaxunit-test-writer` — это форма
`owner/repo`, `skills` понимает ее как сокращение для GitHub-репозитория
`https://github.com/astrizhachuk/yaxunit-test-writer` и клонирует его:

```
skills add astrizhachuk/yaxunit-test-writer -a claude-code -y
```

Под другого агента — замените `claude-code` на нужное имя (`cursor`, `codex`,
`windsurf`, ...), либо `-a '*'`, чтобы установить сразу во все обнаруженные агенты:

```
skills add astrizhachuk/yaxunit-test-writer -a '*' -y
```

Глобально (для всех проектов):

```
skills add astrizhachuk/yaxunit-test-writer -a claude-code -g -y
```

Текст навыка агенто-нейтрален.

## Обновление

```
skills update
```

Обновляет все навыки, установленные через `skills add`, включая этот.

### Windows

По умолчанию `skills` кладет файлы навыка в общее хранилище `.agents/skills/`,
а в каталог агента (`.claude/skills/`) ставит символьную ссылку на него. `skills update`
делает то же самое, даже если навык был установлен копией. На Windows файловые
инструменты Claude Code не проходят по такой ссылке: `SKILL.md` и
`references/` становятся нечитаемыми.

Поэтому на Windows и устанавливать, и обновлять навык нужно флагом `--copy`.
Повторный `add` подтягивает свежую версию из репозитория и перезаписывает
файлы:

```
skills add astrizhachuk/yaxunit-test-writer -a claude-code --copy -y
```

Если `skills update` уже заменил каталог символьной ссылкой: удалить ссылку
`.claude/skills/yaxunit-test-writer` и каталог `.agents/`, затем выполнить
команду выше.

## Структура репозитория

Содержимое навыка (`SKILL.md`, `references/`, `templates/`) лежит в подпапке
`yaxunit-test-writer/`, а не в корне репозитория — это обходит ошибку установщика
`skills`, из-за которого `SKILL.md` в корне репозитория включает режим
установки, копирующий только сам файл `SKILL.md` без сопутствующих файлов.
На команду установки (`skills add astrizhachuk/yaxunit-test-writer`) это не
влияет.

## Среды разработки

Среду разработки навык берет из контекста и сверяет с файлами проекта:
выгрузку Конфигуратора выдает `Configuration.xml` в корне выгрузки, проект
1C:EDT — `.project` и `src/Configuration/Configuration.mdo`. Если признаки
расходятся с контекстом, навык спрашивает пользователя.

Все, что зависит от формата исходников, вынесено в два reference с одинаковым
набором разделов (признаки формата, расположение проектов, раскладка файлов,
новый тестовый модуль, заимствование объекта для перехватчика, регистрация,
чек-лист формата):

- `references/project-format-designer.md` — выгрузка Конфигуратора;
- `references/project-format-edt.md` — проект 1C:EDT.

Объекты метаданных (тестовый модуль, заимствованный объект для перехватчика)
навык создает средством среды разработки, если оно доступно агенту. Если такого
средства нет — файлами по шаблонам из `templates/`. Для 1C:EDT проверены оба
варианта, результат одинаковый.

Особенности формата 1C:EDT, которые учитывает навык:

- тестовое расширение и основная конфигурация — отдельные проекты EDT;
  основная конфигурация находится по `Base-Project` в `DT-INF/PROJECT.PMF`
  тестового проекта;
- объект — каталог с `.mdo` и модулями рядом, регистрация — строка в
  `Configuration.mdo`; при добавлении модуля к уже заимствованному объекту
  метаданные не меняются;
- флаги общего модуля EDT проверяет как стандартный набор, поэтому тестовый
  модуль — клиент-серверный или серверный набор, а флаги «Вызов сервера» и
  «Глобальный» не переносятся: такие модули YAxUnit не считает тестовыми;
- основная конфигурация может быть собрана с библиотеками конфигурации EDT:
  неизмененные объекты библиотеки лежат вне проекта, путь к их исходникам
  навык берет из описания проекта или спрашивает у пользователя.

## Requirements / Assumptions

Общие допущения:

- Имя расширения с тестами — **`Тесты`** (используется в тексте навыка как
  константа).
- Тесты запускаются в тонком клиенте: контексты выполнения — клиент
  управляемого приложения и сервер. Контексты внешнего соединения и обычного
  приложения в прогоне не участвуют, поэтому соответствующие флаги тестового
  модуля на тесты не влияют.
- Среда разработки, версия платформы 1С, для EDT — версия EDT, и
  идентификатор задачи (для проектного тега) берутся из контекста — среда и
  версии обычно указаны в `CLAUDE.md` проекта. Если чего-то в контексте нет,
  навык спрашивает пользователя.
- Из описания проекта (`CLAUDE.md` и т.п.) навык также берет, какие еще
  расширения есть в проекте и где лежат их исходники: в них он ищет перехваты
  тестируемого и мокируемых методов. Если этого в описании нет, навык
  спрашивает пользователя.
- Папка шаблонов выбирается по версии без номера обновления и сборки: для
  Конфигуратора — по версии платформы (8.3.27.2214 → `templates/8.3.27/`), для
  EDT — по версии EDT (2026.1.3 → `templates/edt-2026.1/`).
- Объекты метаданных навык создает средством среды разработки, доступным
  агенту, а если его нет — файлами по шаблонам из `templates/`. Пример такого
  средства для 1C:EDT — MCP-сервер [`EDT-MCP`](https://github.com/DitriXNew/EDT-MCP)
  внутри запущенной EDT (создание объектов, заимствование в расширение,
  валидация). Конкретный сервер навык не требует: оба варианта работают и дают
  одинаковые метаданные.
- Сигнатуры платформенных методов и типов навык предписывает сверять со
  справочником API платформы, доступным в среде агента, а не брать по памяти
  модели. Пример такого справочника — MCP-сервер
  [`mcp-bsl-platform-context`](https://github.com/alkoleft/mcp-bsl-platform-context);
  конкретный сервер навык не требует.

### Выгрузка Конфигуратора

Каталоги выгрузки расширения `Тесты` и основной конфигурации навык берет из
описания проекта (`CLAUDE.md` и т.п.), а если их там нет — спрашивает у
пользователя. В тексте reference они обозначены как `test/` и `src/` — по
раскладке проектов, созданных из шаблона
[`astrizhachuk/bootstrap-1c`](https://github.com/astrizhachuk/bootstrap-1c):

- `src/` — исходный код конфигурации;
- `test/` — расширение с тестами, `test/CommonModules/` — тестовые модули,
  `test/Configuration.xml` — регистрация.

Шаблоны XML-метаданных есть для платформ `8.3.16` (`templates/8.3.16/`,
формат выгрузки `2.9.1`) и `8.3.27` (`templates/8.3.27/`, формат выгрузки
`2.20`). Формат должен соответствовать платформе: 8.3.16 не загружает файлы
в формате `2.20`. Для других версий — добавить каталог `templates/{версия}/`
по аналогии, взяв формат из выгрузки конфигуратора этой версии.

### 1C:EDT

- Основная конфигурация и расширение `Тесты` — проекты EDT (каталоги с
  `.project`), обычно рядом в одном репозитории.
- Шаблоны `.mdo` (`templates/edt-2026.1/`: новый общий модуль, заимствованные
  общий модуль, справочник, документ, регистр сведений) сняты с файлов,
  которые записывает EDT 2026.1. Для других версий EDT — добавить каталог
  `templates/edt-{версия}/` по аналогии, взяв файлы, созданные этой версией.
- Если основная конфигурация собрана с библиотеками конфигурации EDT, путь к
  исходникам библиотек стоит указать в описании проекта (`CLAUDE.md`), иначе
  навык спросит его у пользователя.
