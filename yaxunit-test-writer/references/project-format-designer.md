# Формат проекта: выгрузка Конфигуратора

Файлы метаданных, их раскладка и регистрация для исходников в формате выгрузки Конфигуратора. BSL-код модулей от формата не зависит.

## Признаки формата

В корне выгрузки лежит `Configuration.xml`.

## Расположение проектов

Где лежат выгрузка тестового расширения `Тесты` и выгрузка основной конфигурации (корни с `Configuration.xml`), указано в описании проекта (`CLAUDE.md` и т.п.). Если там не указано — спроси пользователя; путь не угадывай.

Ниже `test/` — каталог выгрузки тестового расширения, `src/` — каталог выгрузки основной конфигурации.

## Раскладка файлов

Метаданные объекта — файл `[Тип]/[ИмяОбъекта].xml`, модули — в каталоге `[Тип]/[ИмяОбъекта]/Ext/`. Одинаково для `test/` и `src/`.

| Тип объекта                        | Каталог модулей                        | Имя файла             |
| ---------------------------------- | -------------------------------------- | --------------------- |
| Общий модуль                       | `test/CommonModules/ИмяМодуля/Ext/`    | `Module.bsl`          |
| Модуль менеджера документа         | `test/Documents/ИмяДок/Ext/`           | `ManagerModule.bsl`   |
| Модуль объекта документа           | `test/Documents/ИмяДок/Ext/`           | `ObjectModule.bsl`    |
| Модуль менеджера справочника       | `test/Catalogs/ИмяСпр/Ext/`            | `ManagerModule.bsl`   |
| Модуль объекта справочника         | `test/Catalogs/ИмяСпр/Ext/`            | `ObjectModule.bsl`    |
| Модуль менеджера регистра сведений | `test/InformationRegisters/ИмяРС/Ext/` | `ManagerModule.bsl`   |
| Модуль набора записей регистра     | `test/InformationRegisters/ИмяРС/Ext/` | `RecordSetModule.bsl` |

Объект есть в расширении (новый или заимствованный), если есть файл `test/[Тип]/[ИмяОбъекта].xml`.

`ConfigDumpInfo.xml` — служебный файл платформы: не создавай и не правь его, платформа ведет его сама.

## Кодировка и конец файла

Файлы должны совпадать побайтно с тем, что пишет платформа, иначе следующая выгрузка расширения разработчиком даст дельту. Окончания строк (CRLF/LF) нормализует git, а BOM и перевод строки в конце файла — нет.

| Файл   | Кодировка    | Перевод строки в конце файла |
| ------ | ------------ | ---------------------------- |
| `.xml` | UTF-8 с BOM  | нет                          |
| `.bsl` | UTF-8 с BOM  | как в тексте модуля, платформа его сохраняет |

Read не показывает BOM, а Write его не ставит: файл, записанный по прочитанному тексту, получится без BOM. Edit сохраняет BOM существующего файла. Поэтому:

- правь существующие файлы (`Configuration.xml`, `.xml` и `.bsl` заимствованных объектов) только через Edit;
- после создания каждого нового `.xml` и `.bsl` добавь BOM командой ниже. Она меняет только файлы без BOM, повторный запуск безопасен:

```powershell
foreach ($f in @('test\CommonModules\[Имя].xml', 'test\CommonModules\[Имя]\Ext\Module.bsl')) { $p = (Resolve-Path -LiteralPath $f).Path; $b = [IO.File]::ReadAllBytes($p); if ($b.Length -lt 3 -or $b[0] -ne 0xEF -or $b[1] -ne 0xBB -or $b[2] -ne 0xBF) { [IO.File]::WriteAllBytes($p, [byte[]](0xEF, 0xBB, 0xBF) + $b) } }
```

## Новый тестовый модуль

```
test/
  CommonModules/
    [ИмяТестовогоМодуля].xml    ← описание модуля (метаданные)
    [ИмяТестовогоМодуля]/
      Ext/
        Module.bsl              ← код теста
  Configuration.xml             ← регистрация всех модулей
```

**Перед созданием** — проверь, существует ли уже модуль с таким именем (`test/CommonModules/[ИмяТестовогоМодуля].xml`). Если файл есть, модуль уже зарегистрирован: не трогай `.xml` и `Configuration.xml`, работай только с `Module.bsl`.

При создании нового модуля:
1. Создай `test/CommonModules/[ИмяТестовогоМодуля]/Ext/Module.bsl`
2. Зарегистрируй модуль в `test/Configuration.xml` (раздел «Регистрация в `Configuration.xml`»).
3. Создай файл `test/CommonModules/[ИмяТестовогоМодуля].xml`. `{uuidgen}` — уникальный UUID объекта метаданных; каждый модуль должен иметь свой UUID (генерация — раздел «Генерация UUID» навыка).

   Значения `ClientManagedApplication` и `ClientOrdinaryApplication` — по правилу контекстов компиляции из навыка:

   - **ОМ_ (общий модуль)** — прочитай `src/CommonModules/[ИмяТестируемогоМодуля].xml` и скопируй значения `ClientManagedApplication` и `ClientOrdinaryApplication` оттуда.
   - **Остальные типы (Док_, РС_, Спр_ и др.)** — всегда `false`/`false` (только сервер).

   Флаги контекстов, кроме `ClientManagedApplication`, на прогон не влияют: тесты запускаются в тонком клиенте, контексты внешнего соединения и обычного приложения в нем не участвуют. Поэтому `ClientOrdinaryApplication` копируется как есть, в том числе у серверного модуля, а `ExternalConnection` всегда `false`. «Вызов сервера» и «Глобальный» — `false`, иначе YAxUnit не считает модуль тестовым.

   Если средства создания объектов метаданных в среде нет (см. навык), создай файл инструментом Write напрямую — никаких дополнительных скриптов не нужно. Отступы — **табуляция**. BOM и конец файла — раздел «Кодировка и конец файла».

   Прочитай шаблон из `templates/{версия-платформы}/common-module.xml` и подставь значения: `{uuidgen}` → новый UUID, `[ИмяТестовогоМодуля]` → имя модуля, `???` → значения из правил выше.

## Заимствование объекта для перехватчика

Перехватчик — это **adopted**-расширение существующего объекта основной конфигурации. Действия зависят от состояния объекта в расширении:

- **Объект не заимствован** (нет `test/[Тип]/[ИмяОбъекта].xml`) — создай XML-метаданные (ниже) и зарегистрируй объект (раздел «Регистрация в `Configuration.xml`»).
- **Объект заимствован, нужного модуля нет** (например, есть `ObjectModule.bsl`, а нужен `ManagerModule.bsl`) — создай файл модуля и сверь существующий `test/[Тип]/[ИмяОбъекта].xml` с шаблоном версии: если в шаблоне есть блок для перехватываемого модуля (`{расширяемый-модуль}`), добавь такой же блок для нового модуля. UUID не меняй, `Configuration.xml` не трогай.
- **Модуль есть** — метаданные и регистрацию не трогай.

### Общий принцип построения XML

Структура XML перехватчика строится на основе `src/[Тип]/[ИмяОбъекта].xml`:

1. **Корневой тег** (`<CommonModule>`, `<Document>`, `<Catalog>`, `<InformationRegister>`) — новый UUID.
2. **`<InternalInfo>`** — скопировать блок `<xr:GeneratedType>` из src, **заменив все UUID (TypeId и ValueId) на новые**; структура (имена, категории, порядок) остаётся точно такой же. Остальное содержимое `<InternalInfo>` — как в шаблоне версии.
3. **`<Properties>`** — минимальный набор: `<Name>`, `<Comment/>`, `<ObjectBelonging>Adopted</ObjectBelonging>`, `<ExtendedConfigurationObject>{uuid корневого тега из src}</ExtendedConfigurationObject>`. Для документов дополнительно пустой `<RegisterRecords/>`, для регистров сведений — `<InformationRegisterPeriodicity>` и `<WriteMode>` из src. Порядок свойств — как в шаблоне версии.
4. Общие модули не имеют `<xr:GeneratedType>` ни в src, ни в test — `<InternalInfo>` как в шаблоне версии.
5. **`<ChildObjects/>`** — у справочника, документа и регистра сведений сразу после `</Properties>` пустой `<ChildObjects/>`; без него сборка падает («ожидаемое ChildObjects»). У общего модуля этого тега нет.

UUID — раздел «Генерация UUID» навыка (для документа или справочника обычно нужно 11, для регистра 15).

### Шаблоны заимствованных объектов

Строй XML по шаблону из `templates/{версия-платформы}/` — в нем все пункты выше уже учтены:

| Тип объекта      | Шаблон                                 | Нужно UUID |
| ---------------- | -------------------------------------- | ---------- |
| Общий модуль     | `common-module-adopted.xml`            | 1          |
| Справочник       | `catalog-adopted.xml`                  | 11         |
| Документ         | `document-adopted.xml`                 | 11         |
| Регистр сведений | `information-register-adopted.xml`     | 15         |

Подстановки:

- `{новый-uuid}` — каждое вхождение заменяется **своим** новым UUID (корневой тег, все `TypeId` и `ValueId`);
- `{uuid-из-src-xml}` — UUID корневого тега из `src/[Тип]/[ИмяОбъекта].xml`;
- `[ИмяМодуля]` / `[ИмяСправочника]` / `[ИмяДокумента]` / `[ИмяРегистра]` — имя объекта, как в src (в том числе в атрибутах `name` блоков `<xr:GeneratedType>`);
- `???` — значения из src: у общего модуля `ClientManagedApplication`, `ExternalConnection`, `ClientOrdinaryApplication`, `ServerCall`; у регистра сведений `InformationRegisterPeriodicity`, `WriteMode`;
- `{расширяемый-модуль}` (если есть в шаблоне) — имя перехватываемого модуля (`ObjectModule`, `ManagerModule`, `RecordSetModule`); если модулей несколько — повтори содержащий его блок для каждого.

## Регистрация в `Configuration.xml`

Добавь в `<ChildObjects>` файла `test/Configuration.xml` среди тегов того же типа тег, соответствующий типу объекта. Место строки:

- теги этого типа уже упорядочены по алфавиту (без учета регистра) — вставь по алфавиту;
- не упорядочены — вставь в конец группы тегов этого типа (так новый объект добавляет и сам Конфигуратор).

Существующие строки не переставляй. На загрузку и выгрузку порядок не влияет.

```xml
<ChildObjects>
    ...
    <!-- группа по алфавиту -->
    <CommonModule>ОМ_Колеровка</CommonModule>
    <CommonModule>[ИмяТестовогоМодуля]</CommonModule>
    <CommonModule>ОМ_МерныеТоварыВызовСервера</CommonModule>
    ...
</ChildObjects>
```

```xml
<CommonModule>ИмяМодуля</CommonModule>
<!-- или -->
<Document>ИмяДокумента</Document>
<!-- или -->
<Catalog>ИмяСправочника</Catalog>
<!-- или -->
<InformationRegister>ИмяРегистра</InformationRegister>
```

Adopted-объекты регистрируются так же, как новые — просто по имени, без специальных атрибутов.

## Чек-лист формата

- [ ] Файл создан в `test/CommonModules/[Имя]/Ext/Module.bsl`
- [ ] Создан файл метаданных `test/CommonModules/[Имя].xml` с уникальным UUID
- [ ] Модуль зарегистрирован в `test/Configuration.xml` (в `<ChildObjects>`; место строки — по правилу раздела «Регистрация в `Configuration.xml`»)
- [ ] Перехватчик (если объект заимствован впервые): XML построен по шаблону версии (у справочника, документа, регистра есть `<ChildObjects/>`) и объект зарегистрирован в `test/Configuration.xml`; если к уже заимствованному объекту добавлен модуль — его `.xml` сверен с шаблоном версии
- [ ] Все созданные `.xml` и `.bsl` начинаются с BOM, `.xml` — без перевода строки в конце (раздел «Кодировка и конец файла»)
