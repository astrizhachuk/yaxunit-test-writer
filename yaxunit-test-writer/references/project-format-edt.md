# Формат проекта: 1C:EDT

Файлы метаданных, их раскладка и регистрация для исходников в формате проекта 1C:EDT. BSL-код модулей от формата не зависит.

## Признаки формата

Каталог проекта EDT содержит файл `.project` и файл `src/Configuration/Configuration.mdo`. Метаданные объектов — файлы `.mdo`.

## Расположение проектов

Основная конфигурация и каждое расширение — отдельные проекты EDT (каталоги с `.project`). Обычно они лежат рядом в корне репозитория; имя каталога проекта произвольное.

- **Тестовое расширение** — проект, у которого в `.project` среди `<natures>` есть `com._1c.g5.v8.dt.core.V8ExtensionNature`, а в `src/Configuration/Configuration.mdo` — `<name>Тесты</name>`.
- **Основная конфигурация** — проект, имя которого указано в строке `Base-Project:` файла `DT-INF/PROJECT.PMF` тестового проекта. Каталог проекта найди по `<name>` в его `.project`.

Ниже `<тест>` — каталог `src` тестового проекта, `<база>` — каталог `src` проекта основной конфигурации.

## Раскладка файлов

Каждый объект — каталог `[Тип]/[ИмяОбъекта]/`: метаданные в `[ИмяОбъекта].mdo`, модули — файлы `.bsl` рядом, без подкаталога `Ext/`. Одинаково для `<тест>` и `<база>`.

| Тип объекта                        | Каталог объекта                         | Имя файла модуля      |
| ---------------------------------- | --------------------------------------- | --------------------- |
| Общий модуль                       | `<тест>/CommonModules/ИмяМодуля/`       | `Module.bsl`          |
| Модуль менеджера документа         | `<тест>/Documents/ИмяДок/`              | `ManagerModule.bsl`   |
| Модуль объекта документа           | `<тест>/Documents/ИмяДок/`              | `ObjectModule.bsl`    |
| Модуль менеджера справочника       | `<тест>/Catalogs/ИмяСпр/`               | `ManagerModule.bsl`   |
| Модуль объекта справочника         | `<тест>/Catalogs/ИмяСпр/`               | `ObjectModule.bsl`    |
| Модуль менеджера регистра сведений | `<тест>/InformationRegisters/ИмяРС/`    | `ManagerModule.bsl`   |
| Модуль набора записей регистра     | `<тест>/InformationRegisters/ИмяРС/`    | `RecordSetModule.bsl` |

Объект есть в расширении (новый или заимствованный), если есть файл `<тест>/[Тип]/[ИмяОбъекта]/[ИмяОбъекта].mdo`.

Файлы `.mdo` — UTF-8, отступы — **два пробела**. Если средства создания объектов метаданных в среде нет (см. навык), создавай их инструментом Write напрямую, по шаблонам из `templates/edt-{версия-EDT}/`.

## Новый тестовый модуль

```
<тест>/
  CommonModules/
    [ИмяТестовогоМодуля]/
      [ИмяТестовогоМодуля].mdo  ← описание модуля (метаданные)
      Module.bsl                ← код теста
  Configuration/
    Configuration.mdo           ← регистрация всех объектов расширения
```

**Перед созданием** — проверь, существует ли уже модуль с таким именем (`<тест>/CommonModules/[ИмяТестовогоМодуля]/[ИмяТестовогоМодуля].mdo`). Если файл есть, модуль уже зарегистрирован: не трогай `.mdo` и `Configuration.mdo`, работай только с `Module.bsl` (если его нет — создай).

При создании нового модуля:
1. Создай `<тест>/CommonModules/[ИмяТестовогоМодуля]/Module.bsl`.
2. Создай `<тест>/CommonModules/[ИмяТестовогоМодуля]/[ИмяТестовогоМодуля].mdo` по шаблону `templates/edt-{версия-EDT}/common-module.mdo`: `{uuidgen}` → новый UUID, `[ИмяТестовогоМодуля]` → имя модуля.

   EDT записывает в `.mdo` только свойства со значением `true`; свойства со значением `false` в файле отсутствуют. Контексты компиляции — по правилу из навыка:

   EDT проверяет, что набор флагов общего модуля соответствует одному из стандартных типов модуля, поэтому флаги ставятся набором, а не по одному. Тестовый модуль — один из двух наборов:

   - **клиент-серверный** — все четыре строки шаблона (`clientManagedApplication`, `server`, `externalConnection`, `clientOrdinaryApplication`);
   - **серверный** («только сервер») — удали строку `clientManagedApplication`. Модуль, у которого только `server`, EDT отклоняет.

   Какой набор выбрать:

   - **ОМ_ (общий модуль)** — прочитай `<база>/CommonModules/[ИмяТестируемогоМодуля]/[ИмяТестируемогоМодуля].mdo`. Есть `<clientManagedApplication>true</clientManagedApplication>` — клиент-серверный набор, нет — серверный.
   - **Остальные типы (Док_, РС_, Спр_ и др.)** — серверный набор.

   Флаги `serverCall` и `global` у тестируемого модуля не переносятся: YAxUnit не считает тестовыми модули с вызовом сервера или глобальные, и тесты такого модуля не загружаются.
3. Зарегистрируй модуль в `Configuration.mdo` (раздел «Регистрация в `Configuration.mdo`»).

## Заимствование объекта для перехватчика

Перехватчик — это модуль **заимствованного** (adopted) объекта основной конфигурации. В EDT состав модулей объекта в метаданных не отражается: `.mdo` заимствованного объекта от добавления модулей не меняется. Действия зависят от состояния объекта в расширении:

- **Объект не заимствован** (нет `<тест>/[Тип]/[ИмяОбъекта]/[ИмяОбъекта].mdo`) — создай `.mdo` (ниже) и зарегистрируй объект (раздел «Регистрация в `Configuration.mdo`»).
- **Объект заимствован, файла нужного модуля нет** — только создай файл модуля рядом с `.mdo`. `.mdo` и `Configuration.mdo` не трогай.
- **Модуль есть** — метаданные и регистрацию не трогай.

### Построение `.mdo` заимствованного объекта

Источник — `<база>/[Тип]/[ИмяОбъекта]/[ИмяОбъекта].mdo`. Шаблон — по типу объекта:

| Тип объекта      | Шаблон                                                         | Нужно UUID |
| ---------------- | -------------------------------------------------------------- | ---------- |
| Общий модуль     | `templates/edt-{версия-EDT}/common-module-adopted.mdo`         | 1          |
| Справочник       | `templates/edt-{версия-EDT}/catalog-adopted.mdo`               | 11         |
| Документ         | `templates/edt-{версия-EDT}/document-adopted.mdo`              | 11         |
| Регистр сведений | `templates/edt-{версия-EDT}/information-register-adopted.mdo`  | 15         |

Подстановки:

1. **`{новый-uuid}`** — каждое вхождение заменяется **своим** новым UUID: атрибут `uuid` корневого элемента и все `typeId` / `valueTypeId` в `<producedTypes>`. Состав и порядок `<producedTypes>` в шаблоне совпадают с источником — UUID источника не копируй.
2. **`{uuid-источника}`** — значение атрибута `uuid` корневого элемента `.mdo` источника (не UUID из его `<producedTypes>`).
3. **`[ИмяМодуля]` / `[ИмяСправочника]` / `[ИмяДокумента]` / `[ИмяРегистра]`** — имя объекта, как в источнике.
4. **Свойства из источника** — значения контролируемых свойств (в блоке `<extension>` они помечены `Checked`) копируются из источника:
   - **Общий модуль** — вместо `{свойства-из-источника}` вставь из источника строки `<global>`, `<clientManagedApplication>`, `<server>`, `<externalConnection>`, `<clientOrdinaryApplication>`, `<serverCall>` — те, что в нем есть, в том же порядке.
   - **Справочник** — строку `<checkUnique>true</checkUnique>` оставь, только если она есть в источнике.
   - **Документ** — ничего не копируется.
   - **Регистр сведений** — вместо `{свойства-из-источника}` вставь из источника строки `<informationRegisterPeriodicity>` и `<writeMode>` — те, что в нем есть, именно в этом порядке. Если нет ни одной — удали строку-заполнитель.
5. `<useStandardCommands>true</useStandardCommands>` оставь всегда — EDT записывает его при заимствовании независимо от значения в источнике.

## Регистрация в `Configuration.mdo`

Добавь строку в `<тест>/Configuration/Configuration.mdo` среди строк того же тега в **алфавитном порядке** по имени объекта:

| Тип объекта      | Строка регистрации                                                                   |
| ---------------- | ------------------------------------------------------------------------------------ |
| Общий модуль     | `  <commonModules>CommonModule.[Имя]</commonModules>`                                |
| Справочник       | `  <catalogs>Catalog.[Имя]</catalogs>`                                               |
| Документ         | `  <documents>Document.[Имя]</documents>`                                            |
| Регистр сведений | `  <informationRegisters>InformationRegister.[Имя]</informationRegisters>`           |

```xml
  <commonModules>CommonModule.ОМ_Колеровка</commonModules>
  <commonModules>CommonModule.[ИмяТестовогоМодуля]</commonModules>
  <commonModules>CommonModule.ОМ_МерныеТоварыВызовСервера</commonModules>
  <catalogs>Catalog.Номенклатура</catalogs>
```

Если строк этого тега в файле еще нет — создай группу. Группы объектов идут после `<languages>` в фиксированном порядке:

`subsystems`, `styleItems`, `commonPictures`, `sessionParameters`, `roles`, `commonTemplates`, `filterCriteria`, `commonModules`, `commonAttributes`, `exchangePlans`, `xDTOPackages`, `webServices`, `httpServices`, `wsReferences`, `eventSubscriptions`, `scheduledJobs`, `settingsStorages`, `functionalOptions`, `functionalOptionsParameters`, `definedTypes`, `commonCommands`, `commandGroups`, `constants`, `commonForms`, `catalogs`, `documents`, `documentNumerators`, `documentJournals`, `enums`, `reports`, `dataProcessors`, `informationRegisters`, `accumulationRegisters`, `chartsOfCharacteristicTypes`, `businessProcesses`, `tasks`.

Новую группу вставь сразу после последней из существующих групп, которые стоят раньше нее в этом порядке.

Заимствованные объекты регистрируются так же, как новые — по имени, без специальных атрибутов.

## Чек-лист формата

- [ ] Код теста в `<тест>/CommonModules/[Имя]/Module.bsl`
- [ ] Создан файл метаданных `<тест>/CommonModules/[Имя]/[Имя].mdo` с уникальным UUID; контексты компиляции — по правилу навыка
- [ ] Модуль зарегистрирован в `<тест>/Configuration/Configuration.mdo` (в группе `<commonModules>`, алфавитный порядок)
- [ ] Перехватчик: если объект заимствован впервые — создан `.mdo` по шаблону (все UUID новые, `extendedConfigurationObject` = `uuid` источника, свойства из источника) и объект зарегистрирован в `Configuration.mdo`; если объект уже был заимствован — добавлен только файл модуля
